# Three silent defects in a profile-based imputer: NaN-poisoned sums, an ungated leave-one-out, and a positional misalignment

Date: 2026-10-25
Competition: 2026-ieee-big-data-traffic-flow-bench
Finding: Moving a verified pandas implementation to array-indexed accumulators introduced three defects that each cost score without raising an error, and all three were invisible in the headline metric because the neighbourhood features carry most of the signal.
1. **NaN-poisoned sums.** `np.add.at(sum_, (slice(None), slot, dow), values.T)` with a NaN in `values` writes NaN into the accumulator, and one NaN observation permanently destroys that (link, slot, weekday) cell's mean even though the count only tracks finiteness. 40% of the speed profile cells were NaN, i.e. silently imputed as 0 by `nan_to_num`. Fix: `np.nan_to_num(values.T)` on the way in, exactly as the flow accumulator already did.
2. **Ungated leave-one-out.** Subtracting the scored day's own observation is only correct when the scored day is *inside* the profile window. The code subtracted whenever the split was `train`, so a holdout day (e.g. June 21 with a profile over June 1-20) lost a value it never contributed and, whenever its (link, slot, weekday) count was 1, the count went to zero and the feature became 0. Fix: keep the set of days the profile was built from and gate the subtraction on membership.
3. **Positional misalignment.** The leave-one-out arrays were built with `wide(p).reindex(columns=links)` and then indexed positionally with `own[ti, li]`. Any difference in row order or row set between the pivot and the day's grid silently subtracts a different timestamp's value. Fix: reindex on the timestamp axis too (`reindex(index=idx, columns=links)`).
Measured effect: on the same D12_I5_N holdout (June 21-30, official Task-1 arithmetic, conserve applied) the model scored 0.9333 with the defects and 0.9351 with them fixed, i.e. +0.0018; the pipeline's headline gain over the shipped rule (0.9079) went from +0.0254 to +0.0272. The defects' real danger is not the size of the loss, it is that a profile feature can be 40% garbage while the model still looks fine, because the model routes around a bad feature rather than failing.
Evidence: state_model.py before/after: NaN fraction of `s_sum` where `s_cnt > 0` 0.398 -> 0; prof_s column fraction exactly 0.306 -> the value matching a pandas groupby reference (RMSE vs reference 62.66 -> exact); verify_state_model.py D12_I5_N 2030-06-21..30 model+conserve 0.9333 -> 0.9351.
Applies when: hand-vectorising a target-encoding/profile feature that was first validated in pandas. Add a direct check of the accumulator against a `groupby` reference, and a check of the *distribution* of the emitted feature (fraction exactly 0, fraction NaN) rather than only the end metric.
