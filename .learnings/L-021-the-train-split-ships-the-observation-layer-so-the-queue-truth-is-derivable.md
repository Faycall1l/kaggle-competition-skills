# The train split ships the observation layer, so the Task 2 queue truth is derivable - build a 60+ window proxy instrument
Date: 2026-10-22
Competition: 2026-ieee-big-data-traffic-flow-bench
Finding: The public release gives exactly 10 Task 2 windows per corridor per split (5 onset + 5 ongoing) and withholds every label, so the queue model can only be tuned against 10 samples (or an unverifiable pseudo-truth). The TRAIN split, however, ships the unmasked observation layer `corridors/<panel>/train/mainline_states/year_month=*`. Measured: the released `window_history.parquet` values are bit-identical to that layer (speed/flow/pct_observed/is_score_eligible agree 1.0000 on every compared cell), and the Task 1 regime masking does NOT apply to Task 2 - the duty-cycle missingness is the only gap. Therefore the queue label (`speed <= v_cut`, `v_cut = 0.60*free_speed`, no v_cut column in fd_parameters.csv) can be reconstructed for ANY origin, and the official scorer `score_task2.py` can score locally-generated windows unchanged. Method: generate windows following the published rules, then expose them as a fake split through symlinks (`<root>/task2/<panel>/train -> <proxy dir>`) so every official tool (`build_task2_persistence_submission.py`, `score_task2.py`) runs on them with no code change. Yield: 63 windows from June 2030 (24 onset / 39 ongoing) and 66 from July (27 / 39) instead of 10, with the organizer's own IoU aggregation.
Evidence: released window_history vs train layer: 258 rows/timestamp, speed equal 1.0000, NaN fraction 0.186 vs 0.186; persistence baseline on the 63 June proxy windows: S_queue 0.2101 (onset 0.0000, ongoing 0.4202) vs 0.2883 on the 10 released train windows; official scorer accepted the symlinked split unchanged
Applies when: a competition ships an unmasked/observation layer for the train split and a per-window metric that can be rebuilt offline - mine more windows instead of tuning on 10
